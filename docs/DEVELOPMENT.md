# 第二代开发指南

适用版本：`0.2.0-beta.1`，已部署本机并发布 GitHub 预发布版本，发布入口见[维护交接](SESSION_HANDOFF.md)。当前功能和验证结论分别见[功能指南](COLLECTION_FEATURES.md)与[验证摘要](VERIFICATION.md)；历史审计和部署过程见[归档](archive/README.md)。

## 项目与运行

本仓库用于第二代开发。代码、依赖、数据、会话与管理来源均与第一代隔离；正式部署使用独立代码快照和私有状态目录，具体模板见[部署说明](../deploy/v2/README.md)。本机当前运行位置集中记录在[维护交接](SESSION_HANDOFF.md)。

静态脚本及样式按实际内容生成哈希 URL，HTML 不缓存；资源改动无需手工修改查询版本。浏览器检查必须覆盖保留旧缓存的升级场景，避免新页面与旧脚本混用。

```sh
npm ci --ignore-scripts
npm run collector:install
npm run verify
TW_RUNTIME_MODE=read-only npm start
```

安装器将固定版本及 wheel 哈希写入独立 `.venv`，不使用上游自动更新或源码安装脚本。运行需要 Node.js 22+ / Python 3.11+。Python 的 `--version` 入口验证固定源码哈希和依赖导入，不发起网络请求。面板的“检测采集器”使用该入口。

| 环境变量 | 默认值 | 含义 |
|---|---|---|
| `HOST` | `127.0.0.1` | 监听地址 |
| `PORT` | `8788` | v2 独立端口 |
| `DATA_DIR` | 项目 `data/` | 本实例独占私有目录，运行用户需有写权限 |
| `TW_RUNTIME_MODE` | `development` | 禁止外部采集、调度和发送 |
| `PUBLIC_ORIGIN` | 未设置 | 公网部署时指定独立 HTTPS 来源 |
| `TRUST_PROXY_TOKEN` | 未设置 | 仅受信任反向代理使用，见部署指南 |

`read-only` 允许手动测试采集，调度、AI 自动翻译、AI 手动测试和 Telegram 均关闭；`live` 启用 twscrape 调度和发送，允许手动发送 hi 测试，并允许另行配置启用 AI 自动翻译。只接受 `development`、`read-only`、`live` 三种模式，其他值启动时即拒绝。模式不能通过网页配置改变。

首页与设置的布局、五类导航、草稿和错误定位规则见[界面说明](DASHBOARD_REDESIGN.md)。浏览器专项 `scripts/browser-redesign-smoke.cjs` 使用隔离的真实后端和本机 TLS 对端。

面板正常 live 模式不显示常驻模式横幅，顶栏继续显示运行、暂停和连接状态；加载、开发、只读及暂停/恢复未确认提示保留，设置故障恢复后收起横幅。

配置包含账号/回复、List、Latest 搜索来源，每页请求条数（1–50）、检查间隔（30–3600 秒）、筛选、暂停状态、Telegram 目标、媒体与背景补充设置。默认 X Cookie 可与额外会话并用；会话标签、启用状态和受控代理属于配置，Cookie 与 Telegram token 保存在实例私有 `secrets.json`，不回显已有值。采集器固定为 twscrape，不提供任意可执行路径配置。已有第二代配置中的未知字段会被忽略，下一次保存只写当前有效字段。

提交来源列表时采用整单严格校验：非法来源、重复身份、超过 100 个来源或非法采集参数均返回 400，不修改配置、凭据或待发队列。`accounts` 字段缺省仍表示保留原值，显式空数组表示删除全部来源。面板清空已有来源的必要字段会阻止保存并保留草稿；新建空白占位行可以忽略。删除或改变来源身份会移除旧基线和旧队列，存在待发送消息时必须另行明确确认；服务端按最新队列独立核对，失败时不保存，详见[功能指南](COLLECTION_FEATURES.md)。仅修改筛选不清除旧待发送项。采集/Telegram 测试前自动保存失败时不会发起后续测试，也不会清掉输入中的凭据草稿。

AI 翻译在原文持久入队后运行，只改变 Telegram 展示，不修改原文、关系、检查点或发送确认；失败回退原文。配置、语言判断、内存缓存和 hi 测试的规则集中在 [AI_TRANSLATION.md](AI_TRANSLATION.md)。

面板保存配置与凭据时，先将完整提交意图同步到私有 `config_transaction.json`，再依次同步两份状态文件，最后删除并同步事务记录。每次读取配置或凭据前都检查未完成事务：完整恢复后才返回结果，存储故障或损坏状态会停止读取。保存失败不再承诺已经回滚；操作可能在存储恢复后完成，应重新载入核对。原有无事务记录的第二代文件仍可直接读取。事务记录含凭据，权限为 0600，禁止公开或放入报告；降级到旧代码前必须先完成该事务。

暂停/恢复控制在读取和保存配置之前，先取消旧任务并让调度停止。读盘、rename 或目录 fsync 失败时返回 500，当前进程保留 `controlPending` 停止标记；后续 tick 不会因磁盘恢复自行重启采集/投递。面板显示“已停止，等待确认”，允许重新暂停或恢复；成功保存配置也会按已保存的暂停状态解除该标记，失败保存不会解除。这个标记仅存在于当前进程，进程重启后仍按磁盘 `paused` 值运行，因此故障后应先恢复存储并明确保存所需状态，不能把失败请求当作已持久暂停。已开始的网络发送无法撤回，成功返回后仍需确认队列，避免人为制造重发。

## 采集结构

```text
面板 / worker
  → lib/x-sessions.js（会话健康、按操作冷却、固定补采身份）
  → lib/twscrape.js（串行查询、90 秒总截止、每轮最多 5 页）
  → collector/bridge.py（stdin JSON；固定 twscrape 签名和操作元数据）
  → X 单页 GraphQL 响应
  → lib/evidence.js（私有证据原子落盘）
  → lib/twscrape-timeline.js（严格整页校验）
  → lib/collector-catchup.js（完整页与游标跨轮保存）
  → 完整覆盖后写持久 outbox，独立投递任务逐部分发送与确认
```

使用固定 twscrape 提交 `63f61a518e576ea5c132f1156c03dda0520d76c1`，该提交仍声明 0.20.1，不宣称上游已正式发布 0.21.0。适配器调用其签名算法及 GraphQL 操作/feature 定义；没有使用会静默丢页的高层迭代器、模型解析器或账户池。

一轮只使用一个凭据会话，持续补采固定同一会话及凭据/代理摘要；凭据通过子进程标准输入传递，不进入命令行参数。Python 仅允许 HTTPS `x.com` 的固定入口，以及不带凭据的 `abs.twimg.com` 脚本。可显式配置受限 HTTP(S) 代理；所有重定向、环境代理、遥测和上游 dump 均关闭。客户端有界复用，用户身份缓存绑定凭据；限流按会话与操作持久保存，只对临时网络/指定上游故障进行有限重试。协议及预算见 [collector/README.md](../collector/README.md)。代码不提供密码/邮箱/TOTP 登录。

每个响应在进入 Node 前将大整数与 ID 转为字符串。响应文档中 GraphQL 错误不会被忽略；未知结构、混合坏条目、身份冲突、重复 ID 内容变化、缺失游标或循环游标都会使本轮失败。引用/转发对象的正文缺失不会抹掉正文完整的父推文及已知关系 ID。普通帖 `legacy.truncated=true` 且没有完整 `note_tweet` 时整页失败，不把预览正文入队，也不推进检查点。原始页面仍按正常规则留存证据。完整长正文保存在证据和待发送队列，Telegram 按长度限制展示。其他作者的回复模块记录只保留证据，不以监控账号名义推送。已遇到的历史编辑关系会保留，但最新 ID 增量监控不能发现所有旧帖后续编辑。

重复记录的作者显示名称作为可补充资料合并，作者资料省略不会冒充正文编辑；正文、身份、时间和关系冲突仍拒绝。转推外层为截断包装文本且内层身份/正文可信时，使用内层普通正文或 note_tweet 补全展示内容，保留外层 ID、作者、时间；内层不可用时，只有未明确标为截断的完整外层正文可以继续处理。明确截断的外层缺少完整 note 或已验证的完整转推正文时，同样整页失败。请求关闭推广内容，意外收到的推广条目仍不能建立覆盖边界，本轮保持失败关闭。

首次采集不会历史重推：取得包含已验证普通时间线条目的整页或终点后建立基线。后续翻页到非置顶、非模块的普通条目覆盖旧水位，或明确终点。每页完整保留；`fetch_count` 是请求提示，不是截断长度。5 页内未覆盖旧水位时不推进检查点，保存完整页面、游标与固定上界，后续轮次/重启继续补采。整段验收后先提交队列，再清理补采阶段；已完成阶段可在 X 冷却时本地恢复，不把本地回放记作新认证成功。

单任务最多 100 页 / 1000 条 / 6 MiB / 7 天，全局最多 32 个任务 / 64 MiB。坏页、游标循环、过期、绑定改变或容量耗尽会明确停止；“重新开始补采”仅删除阶段，保留旧水位和待发消息，重新核对缺口，不跳过历史。搜索另外使用首次监控边界和 24 小时 ID 重叠窗口接收迟到索引，筛选和跨来源去重规则见功能指南；这些能力不保证无限历史完整性。

## 证据与持久性

证据保存为 `DATA_DIR/evidence-<round>-<page>.json`，包括操作、时间、规范化响应文档和 SHA-256。不保存请求头/Cookie；万一响应回显当前凭据，落盘前先替换。ID 的字符串化和凭据脱敏意味着它是保留内容的 JSON 证据，不是逐字节网络抓包。

数据目录必须权限 0700，证据文件 0600；文件和目录 fsync 完成后才解析覆盖边界。单个证据最多 8 MiB，累计最多 64 MiB / 128 文件，保留最多 7 天；清理在下次写入时执行，不在当前轮内清理本轮证据。它是有限诊断窗口，不是永久归档库。

认证、配置、队列与证据访问共用私有目录校验；已存在的非私有目录会被拒绝，不会自动修改权限。状态文件的 rename/unlink 若失败或目录同步失败，后续读写必须先重新确认目录持久性；不能因为新文件已可见就当作提交成功。

新建数据目录还需要持久化父目录项。每个进程首次使用数据目录时，会同步该目录及祖先目录，成功后才接受状态或证据；中途失败保留待同步步骤供重试。运行用户需要可读取这些祖先目录，底层文件系统需要支持目录 fsync；不会自动 chmod 祖先目录。

后页失败时保留已收到页的证据，但整轮不推进采集水位。采集水位与发送确认分开：`acquisitionWatermark` 只来自普通时间线的已验证边界，旧 `watermark` 保留已观察到的最大 ID 以校验队列；较新的置顶/模块记录不能抬高采集检查点。完整记录先落入 outbox，发送成功后才确认。状态损坏、目标改变、容量满或写盘失败会明确停止。队列上限保持每账号 1000 条、总共 5000 条、6 MiB。已存在的第二代队列保持可读，不会因本次清理重建基线；不再自动导入第一代 ID 文件。如果仅发现旧 `sent_ids.json` 而没有有效第二代队列，将停止并要求显式迁移。Telegram 成功后确认前崩溃存在不可避免的重发窗口。

队列兼容读取版本 1，扩展来源、内容、筛选、搜索去重或媒体计划采用版本 2。原文先持久捕获；可选详情、讨论串和 AI 翻译仅影响展示。正文和媒体计划冻结后逐部分确认，重启从未确认部分继续；跨来源同目标同 ID 共用确认。投递独立公平轮询，慢 AI 或 Telegram 不阻止采集继续，暂停和配置代次仍约束新请求。版本 2 扩展状态禁止直接交给旧代码，回退工具对无法无损表达的状态明确拒绝，见[迁移说明](MIGRATION.md)。

## 验证与维护

`npm run verify` 运行 JS 语法检查、全部 Node 测试和 Python 测试；浏览器验证独立运行 `scripts/browser-smoke.cjs`（实际隔离服务）、`scripts/browser-capabilities-smoke.cjs`（新功能合成接口）和 `scripts/asset-cache-browser-smoke.cjs`（旧缓存升级），见[验证记录](VERIFICATION.md)。普通测试不访问 X 或 Telegram，Python 原生传输测试只访问临时本机 TLS 服务。

完整链路拟真使用 `npm run test:simulation`；真实后端浏览器与真实时钟观察分别为 `npm run test:simulation:browser`、`npm run test:simulation:soak`。外部对端为本机 TLS 模拟，应用桥接/签名/存储/投递实际运行；压力场景显式加速时钟，soak 保留真实调度。安装要求、复现命令与替代边界见[拟真演练指南](../scripts/simulation/README.md)。

真实采集、投递与生产迁移需要对应任务授权；不得将凭据复制进开发仓库。离线测试和 hi 连通结果不替代真实采集或端到端投递，已完成项目与尚未验证范围以[验证摘要](VERIFICATION.md)为准。

CI 模板还未启用，历史原因与启用方式见 [CI 状态](../.github/CI.md)。本地验证不依赖工作流权限，不能把模板当成 Actions 已运行。生产迁移参见 [MIGRATION.md](MIGRATION.md)。
