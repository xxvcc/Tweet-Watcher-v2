## 回退准备

`pre-cutover/v1-data` 保存停机后的完整私有快照，`final-migrated` 保存实际导入状态。回退须将 v2 在迁移后新增的确认和 pending 合并回 v1，不能直接恢复旧快照。

已对接管后的当前状态执行只读回退检查：生成独立候选、通过实际 v1 队列结构校验，生产写入为 0：

```sh
sudo node /var/lib/tweet-watcher-v2-cutover-20261029/rollback.cjs --check
```

如确需回退，执行 `--execute`：先停止 v2，读取最终状态并重新校验，备份 v2 私有数据，再安装合并后的队列、恢复 v1 代理及服务。任何检查失败都停止，不能绕过。该执行模式本次没有用于生产回退；已验证的是转换/演练及当前状态候选。

回退边界：v1 正文上限为 12,000 字符；新置顶/模块使最大观测 ID 超过普通检查点、无法交代交接消息去向、目标变更或确认保留范围不足时，工具拒绝自动回退，需单独处理。普通消息的至少一次交付与崩溃重发窗口仍存在。
