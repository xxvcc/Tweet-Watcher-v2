# 第一代到第二代：迁移与回退

本指南说明第一代到第二代的状态迁移和回退约束。2026-10-29 已完成本机生产交接，v2 为唯一发送实例；当次逐账号采集、确认 ID 和演练结果保留在[首次切换记录](archive/2026-10-29-cutover.md)，当前验证范围见[验证摘要](VERIFICATION.md)。

## 切换前

1. 在独立来源、端口、系统用户和数据目录启动 v2 的 `read-only` 模式。配置 X 会话，手动验证每个目标及完整页覆盖。
2. 选择一次迁移窗口。停止第一代调度并确认没有正在进行的采集或 Telegram 请求，记录停止时间。
3. 为第一代数据和代码版本做私有快照，核对发送队列、目标和最后确认状态。禁止两代同时向同一 Telegram 目标发送。
4. 处理已有待发送消息。最容易核验的方案是先排空第一代队列；若不能排空，保留快照并单独制定逐条交接，不能直接把它们当成已发送。

## 水位与交付

第二代默认首次取得有效快照后只建立基线；直接空数据启动会跳过迁移窗口内的历史记录。不能用这一行为假装无缝迁移。迁移时需逐账号核对停止点、已发送集合、未发队列与第二代覆盖范围，再导入经过验证的状态，或人工核对窗口内记录。

现在提供保守的离线转换工具 [scripts/migrate-state.cjs](../scripts/migrate-state.cjs) 和纯函数 [lib/migration.js](../lib/migration.js)。它们只生成独立候选，不安装状态、不修改源文件、不迁移配置或凭据、不发送消息。输入必须绑定完整源状态摘要、账号、目标摘要和逐账号真实覆盖报告；调用者须核验原始证据文件。待发未排空、未知缺口、空基线、状态不一致或普通时间线边界落后旧水位均拒绝。验证窗口内尚未确认的新记录先进入 pending，再更新采集检查点。

```sh
node scripts/migrate-state.cjs migrate \
  --input /private/migration-input.json \
  --output-dir /private/new-candidate
node scripts/migrate-state.cjs rollback \
  --input /private/rollback-input.json \
  --output-dir /private/new-rollback-candidate
```

输入格式对应纯函数 `migrateState()` / `rollbackState()` 的参数；合成示例见 [test/migration.test.js](../test/migration.test.js)。CLI 要求当前用户拥有的私有目录/文件，拒绝仓库内目录、软链接及已有输出目录。生成 `delivery_state.json`、初始化标记和最后写入的 `migration-manifest.json`，目录 0700、文件 0600。源文件必须来自停止唯一发送实例后的最终快照，不能直接安装运行期间的早期候选。

不自动导入第一代 ID 文件；检测到只有旧 ID 文件而没有第二代队列时会停止。不能共用 DATA_DIR，不能复制第一代密码、会话、整个目录或依赖来替代字段明确的迁移。X/Telegram 凭据只在已授权交接时通过私有文件白名单传递，v2 的认证材料独立生成。

完成核对后显式启用 v2 `live`，保留 v1 停止，观察新记录入队、送达和确认。长期停机超过 5 页的追赶范围会失败关闭；需要单独补采，不自动跳水位。

## 回退

停止 v2 并确认请求结束，保存其状态和已确认消息。不能简单恢复旧快照后立即启动 v1，否则可能重发 v2 已经投递的记录。应合并迁移期间的交付确认并处理仍在队列中的消息，再恢复唯一发送实例。

回退工具保持 v2 新增确认和 pending，确认缓存满时仅可裁剪受原水位保护的旧确认。若丢失交接消息去向、正文超过 v1 的 12,000 字符限制、最大观测 ID 超过普通检查点或出现目标/内容冲突，则拒绝自动回退。必须先解决原因，不能忽略报错。当前实例的私有执行器及已完成的 `--check` 见[切换记录](archive/2026-10-29-cutover.md#回退准备)；`--execute` 本次未在生产执行。

Telegram 本身没有本程序可用的事务幂等键，发送成功而本地确认失败时仍可能重复。该限制同时适用于两代，测试通过不等于恰好一次交付。
