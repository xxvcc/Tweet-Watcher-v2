# 架构与后续范围

适用版本：`0.1.0-beta.3`。v2 已完成本机生产交接；实际验证范围见 [VERIFICATION.md](VERIFICATION.md)，首次切换过程见[归档](archive/2026-10-29-cutover.md)。

## 项目边界

v2 源自第一代 v3.5.0，保留 Git 历史、MIT 归属及沿用的面板、认证、调度和持久队列。采集器仅使用固定 twscrape；旧采集程序、依赖、模式和接口兼容入口已移除。

两个项目不共享可写依赖、运行数据、会话密钥或管理来源。跨代修复须单独移植、验证并记录来源提交。默认关闭外部采集和发送，只有进程启动时显式选择 `read-only` 或 `live` 才开放相应能力。

## 当前实现

| 层 | 职责 |
|---|---|
| Node 面板与 API | 中文界面、认证、CSRF、账号和 AI 配置、状态与日志 |
| Python 桥接 | 固定 twscrape 签名和元数据、有界单页请求、字符串 ID |
| Node 采集校验 | 先持久保存整页证据，再核对身份、正文、关系和覆盖边界 |
| 调度与持久队列 | 完整覆盖后推进检查点，保留 pending，发送后单独确认 |
| AI 翻译 | 原文入队后翻译非中文内容，失败回退原文；支持独立 hi 测试 |
| 状态迁移工具 | 生成离线迁移/回退候选，拒绝未知缺口或丢失确认 |

一份 X Cookie 会话串行服务多个监控目标；多个目标不等于多登录账号池。保留已遇到的 repost、quote、reply 与 edit 关系，不代表扫描所有历史编辑。

## 后续范围

1. 补充自然新增推文经采集、翻译、队列到 Telegram 的真实端到端案例及持续运行观察。
2. 设计超过单轮 5 页 / 500 条 / 90 秒预算后的持续补采，不以跳过水位掩盖缺口。
3. 有明确需求时再增加多登录账号池、会话轮换、文章正文或完整历史编辑扫描。
4. 取得工作流写权限后启用 [CI 模板](../.github/CI.md)；当前验证来自本机运行。
