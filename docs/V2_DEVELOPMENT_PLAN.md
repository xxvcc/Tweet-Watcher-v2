# 第二代结构与维护计划

更新：2026-10-23。当前版本 `0.1.0-beta.2`。本文件记录已经实现的结构与后续范围；最初骨架规划可在 Git 历史中查阅。

## 已确认的项目边界

第二代使用独立公开仓库 [Tweet-Watcher-v2](https://github.com/xxvcc/Tweet-Watcher-v2)，本机开发目录 `/www/tweet-watcher-v2`。第一代继续独立维护，生产目录 `/www/tweet-watcher`、开发副本 `/www/tweet-watcher-v1-dev`。

第二代保留源自第一代 v3.5.0 的 Git 历史、MIT 归属和仍在使用的面板、认证、调度及持久发送队列。旧采集程序、依赖、运行模式、接口兼容入口、部署文件和重复文档已清理；本地只保留第二代 origin remote。

两个项目不共享可写依赖、运行数据、会话密钥或管理来源。第二代数据路径会拒绝第一代生产目录，不能通过软链接绕过。日常开发在相应开发副本进行，跨代修复需要单独移植、验证并注明来源提交。

## 已实现的结构

- 原生 Node.js 提供中文面板、认证、账号配置、实时状态/日志、调度和 Telegram 发送。
- 固定 twscrape 源码提供请求签名和操作元数据；Python 桥接只进行有界单页请求，不调用宽松分页迭代器。
- Node 对完整响应先保存私有证据，再校验身份、条目、关系、顺序和游标，只有覆盖完整才推进采集检查点。
- 一份原子队列同时持有待发送内容与检查点；网络、解析、存储和容量失败不能伪装成成功。发送成功后单独确认。
- 只支持 development、read-only、live 三个进程启动模式。配置页面不能改变模式或执行器。
- 一个 X Cookie 会话串行监控多个目标，运行与测试使用独立数据目录。

安装和运行细节见 [DEVELOPMENT.md](DEVELOPMENT.md)，实际测试与边界见 [VERIFICATION.md](VERIFICATION.md)。选型时的审查资料保存在 [research](../research/twscrape-20261023/README.md)，其中历史对照不表示仍安装旧采集器。
